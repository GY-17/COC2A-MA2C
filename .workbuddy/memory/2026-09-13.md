## 重要:V1 的 174 客户规模是怎么来的(已向用户解释)
- 174 来自 `trucks_and_drones/config.py:17` 的 `num_customers: 174`,是 V1 训练时的 config。
- 它不是运行时旋钮:训练时 `total_nodes = num_depots(1)+num_customers(174)=175` 决定网络结构,权重张量形状按 175 存储进 `.weights.h5`。
- 评估时所有脚本都直接从 config 读 `num_customers` 建网络(无自动识别/无一致性校验)。
- **致命坑**:`MACA2CPolicy.load_weights(..., by_name=True, skip_mismatch=True)`(evaluate_unifiedmaca2c.py:330/348)。一旦 config 的 num_customers 与 V1 训练规模不符,大量层形状不匹配会被**静默跳过**,模型用随机权重跑、不报错、输出垃圾(正是 n=4/成本10 的成因)。
- 结论:换规模 = 重新训练新 checkpoint,不能靠改 config 让 V1 适配其它规模。
- 验证 V1 规模:看 `agent_0_maca2c_actor_*.weights.h5` 的层形状,或确认训练用数据集 `singlecenter-101-n175.txt`(174 客户)。
